# Тестовое задание: Инженер по интеграциям и технической поддержке

Этот репозиторий содержит решения тестовых заданий для вакансии в ООО «МэрТрейд».

## Структура репозитория

- `02-warehouse/` — задача по складской логике (FBS, маркировка, инвентаризация).
- `04-incidents/` — задача по разбору инцидентов по логам (диагностика).
- `06-improvement/` — предложение по улучшению процесса (проактивный мониторинг обмена с 1С).

**Принятые решения**
#Задача 02 (Склад)
Приоритезация: задания сортируются по ship_by (ASC). Более срочные забирают остатки первыми.
Маршрутизация: лист подбора сортируется по адресу ячейки для минимизации пути кладовщика.
Валидация КИЗ: проверка формата и глобальная проверка на дубликаты в рамках одной операции.
Инвентаризация: учитываются уже собранные товары, чтобы избежать двойного списания или конфликтов.
#Задача 04 (Инциденты)
Приоритизация: инциденты ранжируются по влиянию на бизнес (выручка/клиенты) и времени на восстановление (Quick Win). Сначала чиним то, что полностью блокирует продажи, затем разблокируем очереди, потом разбираемся с периодическими ошибками, и в конце — локальные проблемы учета.
Диагностика: упор сделан на поиск корневой причины (root cause) в логах, а не только на симптомы, с предоставлением готовых команд для исправления.
#Задача 06 (Улучшение)
Выбор проблемы: "Обмен с 1С иногда «встаёт»". Это критичная боль, напрямую влияющая на бизнес-процессы и учет.
Роль ИИ: ИИ выступает как L1-поддержка, суммаризируя стек-трейсы в человекопонятные гипотезы и шаги для диагностики, что экономит 10–15 минут времени инженера на каждом инциденте.
